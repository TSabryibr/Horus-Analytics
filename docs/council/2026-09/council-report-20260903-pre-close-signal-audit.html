⚠️ The Ghost Candidate Vulnerability

The Flaw: In DailyScanner.py line 312, is_fresh = is_today | (is_recent & (settings.is_market_open() or daily_preview)).

The Impact: An illiquid stock that traded yesterday (T-1) but had ZERO trades today evaluates as is_fresh=True because is_recent=True and daily_preview=True.

The Risk: If that stock met breakout rules yesterday, it would be re-emitted as a live Pre-Close breakout today with yesterday's stale price!

🚨 Vulnerability Diagnosis: The Ghost Candidate Loophole

In core/DailyScanner.py (lines 309-314), the freshness check is written as: 

if use_live_prices:
    is_today = latest_dates.dt.date == TimeUtils.today()
    is_recent = latest_dates.dt.date.apply(lambda d: settings.is_recent_trading_day(d, max_trading_days=1))
    is_fresh = is_today | (is_recent & (settings.is_market_open() or daily_preview))  # <-- BUG!
else:
    is_fresh = latest_rows['Staleness_Days'] <= 10

During a Pre-Close scan, daily_preview = True. If ticker XYZ did not trade today at all, its latest bar in SQLite is from yesterday. Because yesterday is 1 trading day ago, is_recent = True. Thus (is_recent & daily_preview) = True, and XYZ is evaluated as "fresh" today!

🛠️ The Fix: Enforce `is_today` on Pre-Close (Applied & Verified) COMPLETE 
if daily_preview:
    is_today = latest_dates.dt.date == TimeUtils.today()
    is_fresh = is_today  # In Pre-Close preview, only tickers with genuine live trades today are eligible!
elif use_live_prices:
    is_today = latest_dates.dt.date == TimeUtils.today()
    is_recent = latest_dates.dt.date.apply(lambda d: settings.is_recent_trading_day(d, max_trading_days=1))
    is_fresh = is_today | (is_recent & settings.is_market_open())
else:
    is_fresh = latest_rows['Staleness_Days'] <= 10
