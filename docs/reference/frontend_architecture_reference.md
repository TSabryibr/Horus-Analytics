# Horus Analytics v1.0 — Frontend Architecture & UI Component Reference

> **Document Type:** Diátaxis Reference (Information-Oriented)  
> **Audience:** Frontend Developers, UI/UX Engineers, AI Agents  
> **Framework:** Next.js 16.1 (App Router), React 19, TypeScript  
> **Charting:** TradingView Lightweight-Charts 5.1  

---

## 1. Overview & Design Principles

The Horus Analytics frontend is designed as an institutional-grade dark-mode command cockpit modeled after top-tier quantitative terminals:
- **Zero-Latency Rendering:** Uses TradingView `lightweight-charts` with HTML5 Canvas acceleration for 60fps interaction during high-frequency tick updates.
- **Session-Phase Synchronization:** Dynamically reflects the EGX 4-phase session timeline and suppresses stale-feed warnings during auctions.
- **Fail-Closed Execution:** Prevents accidental live trade placement through staged modal confirmations and Live Arm Guard toggles.

## 3. Core Component Library (`frontend/components/`)

### 3.1 `TradingViewChart` (`components/charts/TradingViewChart.tsx`)
Wrapper for `lightweight-charts`:
- Renders Candlestick series, Volume histogram, and technical overlays (SuperTrend, Hull MA, EMA).
- Automatically draws trade geometry markers:
  - Green horizontal line: Entry level
  - Red dashed line: Stop-Loss level ($1.5 \times \text{ATR}$)
  - Blue dashed line: Take-Profit level ($3.0 \times \text{ATR}$)
- Subscribes to `/ws/live` for real-time candle bar updates without full chart re-renders.

### 3.2 `SessionTimelineBadge` (`components/navigation/SessionTimelineBadge.tsx`)
Displays the real-time EGX session status:
- `PRE_MARKET`: Blue pill (`09:30 – 10:00`)
- `CONTINUOUS_TRADING`: Green pulsing pill (`10:00 – 14:15`)
- `CLOSING_AUCTION`: Amber steady pill (`14:15 – 14:25`) with tooltip: *"Continuous trading halted. Order accumulation for closing price in progress."*
- `TRADE_AT_CLOSE`: Cyan pill (`14:25 – 14:30`)
- `MARKET_CLOSED`: Slate pill (`14:30+`)

### 3.3 `LiveArmGuardModal` (`components/modals/LiveArmGuardModal.tsx`)
Enforces the two-step verification workflow:
1. Validates that `AUTO_TRADE_ENABLED=true`.
2. Validates that the operator has confirmed today's trading plan.
3. Requires explicit toggle confirmation before issuing `POST /api/v1/system/live-execution` with `{"armed": true}`.

## 4. State Management & API Integration

- **SWR / React Hooks:** Handles asynchronous REST data fetching with automatic revalidation and optimistic cache updates.
- **WebSocket Consumer:** A dedicated `useLiveWebSocket` hook connects to `ws://127.0.0.1:8000/ws/live` to receive tick broadcasts and session phase transitions.
- **Local Cache:** Stores non-critical UI preferences (chart timeframe, active watchlist filter) in browser `localStorage`.
