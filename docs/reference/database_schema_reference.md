# Horus Analytics v1.0 — Database Schema Reference

> **Document Type:** Diátaxis Reference (Information-Oriented)  
> **Audience:** Backend Engineers, Database Administrators, Quantitative Developers  
> **Database Engine:** SQLite 3 with Write-Ahead Logging (WAL) & Foreign Key Constraints  
> **ORM Framework:** Peewee ORM (`database/models/`)  
> **Primary Storage:** `horus.db` (or persistent directory configured in `settings.py`)  

---

## 1. Architecture & Concurrency Model

Horus Analytics uses an optimized, embedded SQLite architecture configured for high-frequency financial workloads:
- **Journal Mode:** Write-Ahead Logging (`PRAGMA journal_mode=WAL;`), enabling simultaneous non-blocking concurrent reads while background workers write market ticks.
- **Synchronous Mode:** `PRAGMA synchronous=NORMAL;` balancing durability and high write throughput.
- **Connection Retry:** Wrapped in `atomic_write_retry` exponential backoff to handle SQLite busy states gracefully.
- **Hourly Checkpointing:** Scheduled `PRAGMA wal_checkpoint(PASSIVE);` manages WAL file size.

## 2. Core Model Groups

The database schema is organized into four domain groups under `database/models/`:

```
database/models/
├── base.py       # BaseModel base class & common metadata
├── market.py     # Holidays, Provisioning, Sovereign FX state, AI reports
├── portfolio.py  # Portfolios, Positions, Orders, Ledger Trades
├── signals.py    # Signal runs, Recommendations, Lifecycles, Audits
└── accounts.py   # Multi-client API keys & entitlements
```

## 3. Market & System Telemetry Models (`market.py`)

### 3.1 `ProvisioningState`
Tracks progress and operational health of historical data lake provisioning and backfills.
- `name` (`CharField`, Unique, Primary Identifier, e.g. `"HISTORICAL_SIGNAL_PROVISIONING"`)
- `status` (`CharField`): Status token (`"IDLE"`, `"RUNNING"`, `"COMPLETED"`, `"COMPLETED_WITH_WARNINGS"`, `"ERROR"`)
- `target_trading_days` (`IntegerField`): Target historical lookback (default: 252 days)
- `completed_trading_days` (`IntegerField`): Number of trading days successfully hydrated
- `error` (`TextField`, Nullable): Last error message if backfill failed
- `last_run_at` (`DateTimeField`): Timestamp of the last run

### 3.2 `Holiday`
Maintains official Egyptian Stock Exchange (EGX) non-trading days and market closures.
- `date` (`DateField`, Unique): Holiday date (`YYYY-MM-DD`)
- `name` (`CharField`): Name of the holiday (e.g., `"Eid Al-Fitr"`, `"Armed Forces Day"`)
- `is_confirmed` (`BooleanField`, Default `True`): Operator-confirmed holiday status
- `created_at` (`DateTimeField`): Date added

### 3.3 `SovereignState`
Stores macroeconomic parallel exchange rate and sovereign risk parameters.
- `key` (`CharField`, Unique): Attribute name (e.g. `"USD_EGP_PARALLEL_RATE"`, `"CBE_OFFICIAL_RATE"`)
- `value` (`FloatField`): Current rate or multiple
- `metadata_json` (`TextField`): Supplemental calculation parameters (ADR ratios, cross-spreads)
- `updated_at` (`DateTimeField`): Last update time

### 3.4 `AssetAiReport`
Caches LLM market reports and asset dossiers generated by local Ollama (Gemma 4 31B).
- `ticker` (`CharField`, Index): Stock ticker or `"MARKET_SUMMARY"`
- `report_type` (`CharField`): `"PRE_MARKET"`, `"MID_DAY"`, `"POST_CLOSE"`, `"ASSET_DOSSIER"`
- `content` (`TextField`): Markdown analysis synthesized by the model
- `model_version` (`CharField`): `"gemma:4b"`, `"gemma:31b"`
- `created_at` (`DateTimeField`, Index): Report creation timestamp

## 4. Portfolio & Execution Models (`portfolio.py`)

### 4.1 `Portfolio`
Logical trading accounts segregating execution strategies and risk pools.
- `id` (`AutoField`, Primary Key)
- `name` (`CharField`, Unique): Strategy account name (e.g., `"Intraday Signals"`, `"Swing Signals"`, `"Position Signals"`)
- `initial_cash` (`FloatField`): Starting equity allocation
- `current_cash` (`FloatField`): Unallocated liquid cash balance
- `max_risk_pct` (`FloatField`): Maximum risk allocation per trade (default `0.01` = 1.0%)
- `is_active` (`BooleanField`, Default `True`)

### 4.2 `Position`
Currently open or historical positions.
- `portfolio` (`ForeignKeyField` $\to$ `Portfolio`, on_delete='CASCADE')
- `ticker` (`CharField`, Index): EGX symbol (e.g. `"COMI.CA"`)
- `side` (`CharField`): `"LONG"` (EGX is long-only in v1.0)
- `quantity` (`IntegerField`): Number of shares held
- `entry_price` (`FloatField`): Average execution fill price
- `entry_date` (`DateField`): Date position opened
- `stop_loss` (`FloatField`): Dynamic or fixed stop-loss price
- `take_profit` (`FloatField`): Primary profit target price
- `current_price` (`FloatField`, Nullable): Last marked-to-market price
- `unrealized_pnl` (`FloatField`): Open profit/loss
- `status` (`CharField`, Index): `"OPEN"`, `"CLOSED"`

### 4.3 `Trade`
Historical execution ledger recording filled buy and sell transactions.
- `portfolio` (`ForeignKeyField` $\to$ `Portfolio`)
- `position` (`ForeignKeyField` $\to$ `Position`, Nullable)
- `ticker` (`CharField`)
- `side` (`CharField`): `"BUY"`, `"SELL"`
- `quantity` (`IntegerField`)
- `price` (`FloatField`)
- `commission` (`FloatField`): Transaction fee deducted
- `realized_pnl` (`FloatField`, Nullable)
- `executed_at` (`DateTimeField`)

## 5. Signal Strategy & Governance Models (`signals.py`)

### 5.1 `SignalRun`
Records each invocation of the technical scanner.
- `run_id` (`CharField`, Unique, Primary Key): UUID of the scan run
- `scan_type` (`CharField`): `"INTRADAY_MOMENTUM"`, `"PRE_CLOSE_PREVIEW"`, `"EOD_RECONCILIATION"`
- `timeframe` (`CharField`): `"1m"`, `"5m"`, `"15m"`, `"1d"`
- `tickers_scanned` (`IntegerField`): Count of universe tickers processed
- `candidates_found` (`IntegerField`): Raw candidates detected
- `created_at` (`DateTimeField`, Index)

### 5.2 `SignalRecommendation`
Concrete trading setups emitted by the scanner for operator or bot review.
- `id` (`AutoField`, Primary Key)
- `run` (`ForeignKeyField` $\to$ `SignalRun`)
- `ticker` (`CharField`, Index)
- `strategy_id` (`CharField`): Strategy name (e.g., `"breakout_vsa"`, `"trickster"`)
- `direction` (`CharField`): `"BUY"`
- `suggested_entry` (`FloatField`): Optimal entry limit price
- `stop_loss` (`FloatField`): Initial risk stop
- `take_profit_1` (`FloatField`): First target
- `score` (`FloatField`): Multi-factor composite score ($\ge 65.0$)
- `confidence` (`FloatField`): Confidence percentage ($\ge 0.70$)
- `status` (`CharField`, Index): `"ACTIVE"`, `"PENDING_OPEN"`, `"OPEN"`, `"SKIPPED"`, `"EXPIRED"`

### 5.3 `PublishedSignalLifecycle`
Tracks long-term outcome and attribution for signals published to Telegram or live desks.
- `signal_id` (`CharField`, Unique, Index)
- `ticker` (`CharField`, Index)
- `published_at` (`DateTimeField`)
- `entry_hit` (`BooleanField`, Default `False`)
- `entry_hit_at` (`DateTimeField`, Nullable)
- `tp_hit` (`BooleanField`, Default `False`)
- `sl_hit` (`BooleanField`, Default `False`)
- `outcome` (`CharField`): `"PENDING"`, `"WIN"`, `"LOSS"`, `"EXPIRED"`, `"INVALIDATED"`
- `r_multiple` (`FloatField`, Nullable): Final return in units of initial risk $R$

### 5.4 `SignalAuditEvent`
Permanent audit log tracking system decisions, operator plans, and rule violations.
- `event_id` (`AutoField`, Primary Key)
- `event_type` (`CharField`, Index): `"OPERATOR_PLAN_CONFIRMED"`, `"OPERATOR_DEVIATION"`, `"CIRCUIT_BREAKER_TRIGGERED"`
- `severity` (`CharField`): `"INFO"`, `"WARNING"`, `"CRITICAL"`
- `message` (`TextField`): Descriptive explanation
- `details_json` (`TextField`): Structured payload capturing exact inputs, tickers, and reasons
- `created_at` (`DateTimeField`, Index)

## 6. Schema Migration Guidelines

Horus executes non-destructive schema migrations on application startup via `database/migrations.py`:
1. Use `PRAGMA table_info(table_name)` to introspect existing columns.
2. Add new columns using `ALTER TABLE table_name ADD COLUMN column_name ...`.
3. Avoid dropping or renaming columns directly in production SQLite files; use migration aliases if backwards compatibility is required.
